# ГИС кормовых ресурсов Уалихановского района (проект 019)

Цифровая ГИС-база и интерактивная карта по результатам полевых обследований 2026 г.:
44 площадки почвы и травостоя, 44 точки отбора воды, 11 сельских округов, пробы молока.
Выезды: 6–12 августа и 12–22 сентября 2026 г. (те же 44 точки); на сайте выезд переключается
вверху панели, в карточках оба выезда стоят рядом.

**Сайт:** папка `docs/` → после включения GitHub Pages он открывается по адресу
`https://<ваш-логин>.github.io/<имя-репозитория>/`

## Что где лежит

| Папка / файл | Что это | Кто меняет |
|---|---|---|
| `исходные_данные/Данные_019.xlsx` | **Главный файл с данными**: точки отбора и все анализы по выездам | вы |
| `исходные_данные/` | Остальные исходники: границы OSM, отчёты за август и сентябрь (из них берутся фото), KML, протокол № 212 | вы (кладёте новые файлы) |
| `исходные_данные/фото_дополнительные/` | Ваши фото, например водоёмов (см. ниже) | вы |

| `скрипты/` | Программы, которые из исходников собирают базу и сайт | программист |
| `шаблон/` | Внешний вид сайта (HTML, стили, логика карты) | программист |

| `build/` | Промежуточные файлы | собирается автоматически, в Git не хранится |

## Как устроена сборка

Пять шагов, каждый – отдельный скрипт с пояснением в начале файла:

1. `01_точки_и_анализы.py` – точки и анализы из `Данные_019.xlsx` → база (по всем выездам)
2. `02_границы.py` – граница района и сельских округов из OpenStreetMap, средние по округам и выездам
3. `03_фото.py` – фото площадок и работ из отчёта каждого выезда (+ ваши дополнительные фото)
4. `04_оценка_и_рекомендации.py` – оценки показателей по шкалам для каждого выезда, выводы и рекомендации
5. `05_сайт.py` – интерполяция (IDW) по выездам, молоко и сборка `docs/index.html`

Всё сразу: `python3 скрипты/run_all.py` (около 10 секунд).

## Частые задачи

### Где лежат данные и как добавить новые
Все цифры – в `исходные_данные/Данные_019.xlsx`. Принцип: **точки отдельно, анализы отдельно**.

| Лист | Что в нём | Одна строка = |
|---|---|---|
| `точки` | координаты точек (почва и травостой, вода) | одна точка |
| `почва`, `травостой`, `вода` | результаты анализов | одна точка в одном выезде |
| `молоко` | пробы молока, у каждой свои координаты (обычно – село) | одна проба в одном выезде |
| `микробиота` | микробиологическая активность почвы (результаты ожидаются) | одна точка в одном выезде |
| `выезды` | список выездов и их сроки | один выезд |

Точка определяется столбцами «Сельский округ» и «ТС». Новый выезд – это новые строки с другим
значением в столбце «Выезд», старые строки не трогаются. Пустая ячейка значит «в этом выезде
не определялось» (например, агрохимия почвы в сентябре не повторялась).

**Как добавить следующий выезд:**
1. На листе `выезды` – новая строка (название, период). Порядок строк = порядок на сайте.
2. В листах анализов – строки с этим названием в столбце «Выезд».
3. Если нужны фото из отчёта – положите отчёт в `исходные_данные/` и допишите его
   в `ОТЧЁТЫ` в `скрипты/общее.py`.

**Оценка воды.** Если столбец «Оценка воды» пустой, она считается автоматически по критериям
табл. 16 отчёта: E. coli ≥10 или TDS >3000 – критическая; E. coli 1–9 – высокий риск;
колиформы >100, TDS >1000 или мутность >5 – ограниченно пригодная; любые колиформы или
мутность >1,5 – требует санитарного контроля; иначе – благоприятная. На августе это правило
даёт ровно те же оценки, что в отчёте.

**Выводы и рекомендации по округам** составлены по первому выезду (август) и правятся вручную
в `рекомендации/Рекомендации_по_округам.xlsx`.

**В QGIS** у слоёв `почва_трава`, `вода`, `молоко` есть столбец `выезд`. Чтобы видеть один выезд:
правый клик по слою → «Фильтр…» → `"выезд" = 'Сентябрь 2026'`. Средние по округам – таблица
`средние_по_округам`.

После правок: сохранить Excel → `python3 скрипты/run_all.py` → коммит.
Если в файле ошибка (точка без данных, повтор, неизвестный округ), сборка остановится
и напишет, в каком листе и какая точка.

### Поправить рекомендации по округу
1. Откройте `рекомендации/Рекомендации_по_округам.xlsx`, исправьте текст в ячейках.
2. Сохраните и пересоберите: `python3 скрипты/run_all.py`.
3. Сделайте коммит (см. «Работа с Git»).

### Добавить фото водоёма или площадки
Положите файл в `исходные_данные/фото_дополнительные/` с именем по шаблону
`Округ_ТСномер_вид_порядковый.jpg`, где вид – `вода`, `почва` или `трава`:

```
Карасуский_ТС1_вода_1.jpg
Кулыкольский_ТС3_почва_1.jpg
```
После пересборки фото воды появится в карточке пробы вместо пустой рамки.

### Поменять шкалы оценки (гумус, P, K, урожайность …)
Словарь `SCALES` в начале `скрипты/04_оценка_и_рекомендации.py`: `edges` – границы классов,
`names` – названия классов.

### Открыть базу в QGIS
Перетащите `база/База_019.gpkg` в окно QGIS и отметьте 4 слоя. Цвета подключатся сами.

## Работа с Git – коротко

**Git** хранит историю всех изменений. Каждый сохранённый «снимок» проекта называется
**коммит**. К любому коммиту можно вернуться. **GitHub** – сайт, где эта история хранится онлайн.

Проще всего работать через бесплатное приложение **GitHub Desktop** (desktop.github.com):

| Действие | Где в GitHub Desktop |
|---|---|
| Увидеть, что изменилось | вкладка **Changes** – список файлов и что в них поменялось |
| Сохранить снимок (коммит) | внизу слева: краткое описание → **Commit to main** |
| Отправить на GitHub | кнопка **Push origin** вверху |
| Посмотреть историю | вкладка **History** |
| Вернуть старую версию | **History** → правый клик на коммите → **Revert changes in commit** |

### Первая публикация (один раз)
1. GitHub Desktop → **File → Add Local Repository…** → выберите папку `гис-019`.
2. Кнопка **Publish repository**. Снимите галочку **Keep this code private**, если нужен открытый.
3. На github.com откройте репозиторий → **Settings → Pages** →
   Source: **Deploy from a branch**, Branch: **main**, папка **/docs** → **Save**.
4. Через 1–2 минуты сайт будет доступен по ссылке, которую покажет эта же страница.

Закрыть репозиторий позже: **Settings → General → Danger Zone → Change visibility**.
Учтите: на бесплатном тарифе GitHub Pages у закрытого репозитория отключается.

## Что не попадает в открытый репозиторий

Файлы из `.gitignore`: отчёт `.docx` и протокол `.doc/.docx` (в приложении отчёта есть сканы
актов с подписями и печатями), папка `build/`. Они лежат только у вас на компьютере.
Чтобы выложить их тоже – удалите соответствующие строки в `.gitignore`.
